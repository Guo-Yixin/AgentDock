# 记忆、工作流与交互：0.6 产品闭环

参考 [TechSpar](https://github.com/AnnaSuSu/TechSpar) 的功能卡片、分层表面、琥珀色强调，以及交互结果回写长期资料的思路。AgentDock 的组件、样式和业务实现独立编写，没有复制其源码、标识或素材；不引入面试业务。

## 可用路径

1. 打开任意会话，点击“沉淀为记忆”：使用已有摘要生成本地草稿，保留会话 ID 与来源；报告和助手分析也可以生成草稿。
2. 编辑内容，选择决策、经验、避坑或工作偏好，填写标签和关联项目。草稿不等于已验证事实，用户核实后改为“已确认”。
3. 在记忆库搜索、筛选和导出 Markdown。确认后默认 7 天复查，可以人工选择 1、7、30 天后的下次复查。记忆库可筛选待复查项；这不是系统后台通知或完整 SM-2 算法。
4. 启动跨工具交付、阻塞诊断或每周复盘工作流，关联会话、目标、报告和已确认记忆。来源由服务端按 ID 核实，标题与证据不接受客户端伪造。
5. 当前步骤可“用助手分析本步”，携带工作流快照、关联依据和具体问题。发送前继续预览实际上下文，由用户点击调用 DeepSeek，不自动发送全部记忆。
6. 手动记录每步结论后确认推进。完整复盘可变成新的记忆草稿，下一步可创建待编辑的日程草稿，形成回访闭环。

工作流的完成只代表用户确认了全部引导步骤，不会自动将关联会话或工作目标标记完成。模板不执行 IDE 命令、采集任务或外部自动化。

## 0.8.0 一屏操作路径

记忆编辑通过“内容、分类与确认、来源、复查”标签填写；工作流创建通过“选择模板、名称与项目、依据”填写。启动后默认显示当前步骤，保存步骤、来源与复盘跟进各有独立入口。窄窗口使用下拉切换页面，点击“返回工作资产列表”回到索引；草稿保持挂载，不因切换标签丢失。

助手在进入所选对象时自动生成发送预览，点击“返回聊天”填写问题；生成仍需要点击“确认内容并发送”。回答后的沉淀与日程操作在“保存建议”中，原始聊天在“聊天历史”中。工作台通过“记忆与工作流”入口访问这些能力，无需滑到页面底部。

## 数据与交互约束

- 复用 MySQL 的 `ad_documents`，新增 `memory` / `workflow` 文档类型，不修改工具日志。无需额外数据库或向量服务，账号保护、来源校验与 Worker RPC 继续生效。
- 列表在数据库搜索、筛选与分页，每页最多 5 项，小窗口按可用高度减少。引用选择器展示近期对象；更早会话可以从历史搜索打开详情，再创建记忆。
- 保存与步骤推进在事务内完成，用版本号拒绝其他窗口的过时编辑。重新载入后再编辑，不静默覆盖。已有对象编辑与已确认结论不会被同步改写。
- 记忆上下文包含状态和原始对象引用；工作流上下文包含确认时间、步骤结论和关联来源。不会递归展开引用图或自动读取会话正文，防止循环与无界扩张。归档对象不作为助手上下文。
- 助手的每次上下文仍保留快照和可回跳的来源。已有凭据脱敏与 48000 字符预算继续生效；API 密钥只用于认证头。
- 演示仅使用前端内存数据，不调用数据库或模型；刷新页面会重置新增演示记录。
- 浅色与深色采用共享主题变量；表单、弹窗和新页面适配窄窗口，减少动态效果时移除卡片位移动效。网页和桌面渲染器使用同一套构建。

## 后续阶段

当前实现是可追溯的人工整理与引导式工作流。下一阶段可在真实使用反馈后增加记忆版本比较、用户可控的本地语义检索、模板自定义和工作资产备份；再考虑需单独授权的执行能力。当前没有向量召回、自动记忆注入、无人值守任务执行或多用户隔离。
